# 如喜（RuhI）v0.9.5 基準評測報告（v1.0 系列首發里程碑）

> **評測版本**：`RuhI v0.9.5`（選配輕量神經重排首發里程碑，核心基底 `b54f032`；後續將推進 Stage D1–D4 並以此為基準發布正式 `v1.0.0`）  
> **架構總覽**：`Forward-Viterbi + Backward-A*`（`K=16 / 自適應 K=32`）＋ 詞三元統計底盤（`RLNG0002`，50.34 MB）＋ 選配離線純 Rust INT8 因果字元 Transformer（`RLNM0001`，21.79 MB，`22.59M` 參數）  
> **硬體與推論設定**：`8` 執行緒樹狀批次 GEMM（AVX-512F / AVX2+FMA ＋無鎖自旋執行緒池）、Named Pipe 本地單例常駐（`25 ms` 硬逾時自動回退）、固定參數 $\lambda = 2.25$、`score_margin = 25.0`、`max_trie_nodes = 200`。

## 一、可重現評測指令與規範

所有開發集與基準延遲測試皆可直接透過 `Release` 建置二進位檔於本機重現（嚴禁以人工手調權重過擬合盲測集；`test.tsv` 與 `typing_tw.tsv` 僅於定案後執行單次終檢）：

```powershell
# 1. 建置核心評測與重排器二進位檔
cargo build --release --manifest-path ruhi-core\Cargo.toml --lib --bin ruhi_reranker --bin ruhi_eval --bin ruhi_ngbin --bin ruhi_lkbin

# 2. 開發集離線基準品質閘門（對照 eval_reports/dev_gate_baseline.json）
.\ruhi-core\target\release\ruhi_eval.exe --set dev --gate

# 3. 開發集 N-Best Oracle 上界（比較 K=16 與 K=32 長句召回）
.\ruhi-core\target\release\ruhi_eval.exe --set dev --nbest-oracle --top-k 16
.\ruhi-core\target\release\ruhi_eval.exe --set dev --nbest-oracle --top-k 32

# 4. 開發集（dev.tsv）RLNM0001 神經重排實測
.\ruhi-core\target\release\ruhi_eval.exe --set dev --neural-rerank ruhi_lexicon\data\rlnm_zh_tw.bin --neural-lambda 2.25 --neural-margin 25.0 --neural-max-trie-nodes 200

# 5. 重排器微基準測試（涵蓋短句、構式對比與 18/24 字長句 Trie 節點預算）
.\ruhi-core\target\release\ruhi_reranker.exe --model ruhi_lexicon\data\rlnm_zh_tw.bin --bench --threads 8
```

## 三、長句 `N-Best` 召回上界評估（`K=16` vs. `K=32`）

於啟用神經重排時，當注音音節長度 $\ge 15$ 音節自動放寬搜尋寬度至 `K = 32`（`MAX_ASTAR_POPS = 4096`），離線模式則維持 `K = 16` 以確保純靜態延遲不變：

| 指標（`dev.tsv` 3,640 句） | `K = 16` | 自適應 `K = 32`（$\ge 15$ 音節） | 變動 |
|---|---:|---:|---|
| **Oracle 上界整句命中率** | `88.27%` | **`89.59%`** | **`+1.32 pp`**（多召回 `+48` 句正確整句） |
| **Oracle 上界 CER** | `1.42%` | **`1.23%`** | **`-0.19 pp`** |
| **A\* 候選展開中位延遲 (`p50`)** | `16.46 ms` | **`16.38 ms`** | 幾乎無額外時間開銷 |

## 五、訓練語料純度與推論延遲剖析

1. **全量冷啟動語料與去重**：
   - 於 Google Colab `NVIDIA A100-SXM4-40GB` 以 BF16 訓練 `12,000` 步並匯出 INT8 `RLNM0001`（`22,847,208` 位元組／`21.79 MB`，指紋 `corpus_fingerprint = 0x6f6ff534ce904c9b`）。
   - 收集 **11 組可正常取得之商用安全台灣繁體來源**共 **`103,159,629`** 清潔字元（`11,108,601` 句段；已事先以雜湊對全評估集排重），並採 `40%` `<bos>` 冷啟動切片（50% 單句段＋50% 雙句段）消除句首短前綴機率倒掛；驗證損失 `val_packed_loss = 3.1624`（`ppl = 23.63`）、`val_cold_loss = 3.7930`（`ppl = 44.39`）。
2. **`PrefixTrieBudget` 與 `--threads 8` 延遲表現**：
   - 未受限的 18–24 字長句展開 `K=32` 候選時，前綴樹非葉節點可達 `~270–282` 個（耗時 `25.8–39.5 ms`）。
   - 引入 `select_candidates_with_trie_budget(..., max_trie_nodes = 200)` 動態裁切低機率尾端分歧後，於 `ruhi_reranker --bench --threads 8`（含短句對比與 18 字 `[bench #6]`、24 字 `[bench #7]`）實測 **`p50 = 9.81 ms | p95 = 20.72 ms | max = 20.72 ms`**，全數穩定壓在 `25 ms` 硬逾時安全邊界之內，且 **7/7** 正誤對比句（含句首「已取消南下旅程」「變兩下」）排序完全正確。
